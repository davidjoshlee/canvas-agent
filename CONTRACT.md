# Implementation contract (MVP)

All paths in context and tasks are vault-relative POSIX paths except WorkspaceContext.vault and ToolkitConfig.vault.path (absolute). Source hashes are SHA256 of original file bytes. Do not copy personal data or configuration from siblings.

Public modules and exact signatures:

- `src/config.ts`: `loadConfig(configPath: string): Promise<ToolkitConfig>`; `createConfig(configPath: string, input: {vault: string; baseUrl: string; tokenEnv?: string; courses?: string[]}): Promise<ToolkitConfig>`. Paths resolved relative to config file. Never replace existing config. Default allowlist empty.
- `src/canvas.ts`: `listCourses(config: ToolkitConfig): Promise<Array<{id: string; code: string; name: string}>>`; `syncCourses(config: ToolkitConfig): Promise<{courses: number; written: string[]; notices: string[]}>`. GET only, env token. Discovery lists readable courses; only sync uses the Canvas ID allowlist. Pagination same-origin; sync never overwrites student edits. Refresh only hash-owned files, preserve untracked files with notices. Save manifest at `_meta/canvas-courses.json` with course mappings and roots; private ownership hashes at `_meta/canvas-sync-state.json`. Handle course-code collision by fail before writing. Remote HTML text normalized locally, originals retained; no model extraction.
- `src/workspace.ts`: `inspectWorkspace(vault: string): Promise<WorkspaceContext>`; `selectCourse(context: WorkspaceContext, query: string): CourseContext`. Recognize course-code and safely manifest-mapped directories; skip private `_meta`, dotfolders, credential-like files and symlinks, preserve relative paths; use frontmatter restrictions/ai_policy/redistribution conservatively. Restricted or prohibited material MUST NOT have text in source records. Unknown binary documents get exclusions. Recognize week/assignment/prep paths, guidance in Resources/Guidance or legacy guidance locations, and relevant root AGENTS.md. Read-only scan. CLI context omits source bodies; task show JSON returns approved snapshots. No database prerequisite for existing School Agent vault. Reject missing/ambiguous course.
- `src/workflows.ts`: `workflowFor(kind: "prep" | "assignment", mode?: "outline" | "draft" | "review")` returns versioned instructions and required headings. Prep synthesizes a finished brief, including frameworks and cases when supplied, and answers posted prep questions. Assignment requires an explicit mode; its workflow bounds prompt/rubric coverage, student inputs, open questions, traceable citations, and applicable AI-permission handling. These instructions are embedded in task JSON and TASK.md and mechanically shared with plugin workflow blocks. They guide generation; they do not verify academic quality.
- `src/tasks.ts`: `createPrepTask(vault: string, course: string, week: string): Promise<TaskRecord>`; `createAssignmentTask(vault: string, course: string, sourcePath: string, mode: string, workPath?: string, contextPaths?: string[]): Promise<TaskRecord>`; `readTask(vault: string, id: string): Promise<TaskRecord>`. Prep week is an explicit real Monday. Assignment requires a prompt and outline/draft/review mode; work/context paths are vault-relative, and review requires selected Markdown/plain-text work in a Draft/Drafts folder. Persist immutable source snapshots and human TASK.md under `_meta/tasks/<uuid>/`. Prep selects target-week materials plus course references/guidance; assignment selects its prompt, explicit work/context, recognized course references and all active permitted guidance. Creation and completion share `selectAssignmentInputs` for authoritative snapshots. Neither silently includes the whole course or prior work. Requirements/headings come from `workflowFor`; TASK.md embeds academic instructions, identity, citations, notices and policy limits. Legacy prep records without workflow fields remain readable; new tasks include the workflow.
- `src/completion.ts`: `completeTask(vault: string, id: string, candidateFile: string): Promise<{task: TaskRecord; output: string}>`. Validate schema, authoritative workflow, course/destination, identity, sections and citations; verify source/guidance snapshots and current restrictions. Reject empty, stale, unsafe or privately leaking candidates. Version outputs without overwriting (`01 Prep Brief.md` or `01 Assignment Outline/Draft/Review.md`, then a `.v2.md` sibling); save atomically and persist completion, with identical retries idempotent. Output stays within the course/week Prep destination or Drafts folder beside the assignment prompt, never a model-chosen path. Academic correctness, rubric coverage and AI permission are not guaranteed.
- `src/cli.ts`: Commander entry, `--config` global default `./canvas-agent.config.json`; `init --vault PATH --canvas-url URL [--course ID repeated]`; `courses [--json]`, `sync [--json]`, `context [--json]`, `prep COURSE --week DATE [--json]`, `assignment COURSE --source VAULT_RELATIVE_PROMPT --mode outline|draft|review [--work VAULT_RELATIVE_STUDENTWORK] [--context VAULT_RELATIVE_PATH repeatable] [--json]`, `task show ID [--json]`, `task complete ID --file PATH [--json]`. Human output clear; JSON stable parseable stdout only; errors stderr and exit nonzero, no stack/token exposure. Build dist/cli.js executable shebang.

Each module can depend on shared types but should not run IO on import. Test public exports with Vitest and temp directories; mock Canvas HTTP, no real token/network. Do not implement provider integrations, unattended schedules, or hosted apps in this slice. Assignment tasks are source-bound workflow handoffs; the toolkit itself does not generate assignment content.
